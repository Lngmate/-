# 高校实验室设备预约与共享系统 (LabShare 完整生产级系统)

> 面向高校科研教学与学科建设的“高可用、现代化、多角色协同”实验室大型精密仪器设备全生命周期预约与共享平台。

---

## 一、 项目背景与业务痛点解析

根据项目计划书调研，高校传统实验室管理模式存在以下 4 大核心深层痛点：
1. **设备信息孤岛与透明度低**：依赖线下纸质登记或微信群口头协调，闲置状态不透明，“急需仪器的学生找不到设备，闲置的设备无人知晓”。
2. **预约冲突频发与统筹困难**：缺乏自动化防冲突校验机制，人工协调易撞车；对于需要连续运行数小时甚至数天的精密实验，临时插单和挤占引发矛盾。
3. **跨课题组共享与经费结算壁垒**：仪器多由特定课题组出资购置，缺乏公平透明的机时共享与计费划转规则，“私有化”倾向严重。
4. **履约监管与信用约束缺失**：存在“过度多占、预约爽约、逾期不还”现象，缺乏科学信用约束与黑名单机制。

## 二、 五大特色创新点设计与落地

针对上述核心痛点，本系统在完成完整业务闭环的基础上，重点实现以下五大创新：

### 🌟 创新点 1：绿色节能“伴热/同参拼单”智能推荐引擎（Eco-Batching）
- **痛点**：高温管式炉、XRD衍射仪、真空冷冻干燥机、大型离心机、SEM电镜等设备升降温和抽真空耗电巨大。分散预约导致设备反复冷热循环，损耗寿命且浪费能源。
- **机制**：预约提交时记录工况参数（目标温度、真空度等）。排期引擎自动识别前后 60 分钟内相近工况的实验，提示“伴热拼单”。
- **激励**：拼单双方直接享受 **机时费 8.5 折优惠**，且获得 **优先审批绿色通道**，仪表板实时折算“节能减排度数 (kWh) 与经费减免”。

### 🌟 创新点 2：动态科研履约信誉矩阵与弹性防占座机制（Dynamic Credit Matrix）
- **痛点**：传统封号一刀切，缺乏正向激励；师生多占、迟到、爽约屡见不鲜。
- **机制**：
  - **信誉弹性分（基准100分）**：按时履约并如实提交归还状态反馈 +2 分，提前释放时间槽获加分；
  - **分级权益**：
    - **≥95分（卓越）**：享有黄金时段优先排队权、免导师审批直通特权；
    - **80~94分（良好）**：标准预约权限；
    - **60~79分（预警）**：限制单周最大预约时长，暂停一级高精密设备预约；
    - **<60分（冻结）**：暂停预约，需管理员线下核验重置。
  - **动态超时核销**：超期未签到自动判定爽约并扣减信用分，时间槽立即释放供候补师生抢约。

### 🌟 创新点 3：数字孪生实验室 2D 平面机位交互地图（Digital Twin Lab Map）
- **痛点**：表格展示抽象，师生不清楚设备具体物理位置、周围配套与现场工况。
- **机制**：提供交互式 2D 实验室空间平面图，四大实验功能区全景覆盖，各机台状态实时色彩映射：
  - 🟢 **绿色**：空闲就绪
  - 🔵 **蓝色**：实验运行中（显示当前使用者与倒计时）
  - 🟡 **黄色**：即将生效预约
  - 🔴 **红色**：维保/故障
  - 点击机位即可弹出设备规格、健康度并一键发起快速预约。

### 🌟 创新点 4：设备健康度（Health Score）预测与自适应维保锁
- **痛点**：设备“小病不修、大病报废”，实验中途故障导致数据损毁。
- **机制**：基于累计运行机时、连续高负荷时长动态计算健康得分（0~100）。低于 70 分时系统自动生成维保工单，并在日历中强制插入维保锁定期，防止“带病服役”。管理员完成维保后可一键重置健康度。

### 🌟 创新点 5：跨课题组机时共享与学术合作互助集市（Cross-Group Machine-Hour Trading）
- **痛点**：出资课题组设备“私有化”，跨组借调报销流程繁琐。
- **机制**：支持课题组将闲置机时投放共享池，支持虚拟科研经费自动划转结算，打通校内跨学科仪器共享内循环。

## 六、 快速启动指南

新增“实验任务”入口，支持2至3台设备的顺序工序排程、最短间隔、时间线预览和整单提交。使用方法、算法及一致性边界见 [多设备实验任务预约](backend/TASK_SCHEDULING.md)。

### 1. 启动后端服务 (Go)
请先安装 Go 1.21 或以上版本，并确保 `go version` 可以执行。启动脚本优先使用系统 Go，也兼容项目内的 `go/bin/go.exe`。

双击运行根目录下的 `start_backend.bat`，或在命令行中运行：
```bash
cd backend
go run cmd/server/main.go
# 或使用便携式 Go：
..\go\bin\go.exe run cmd/server/main.go
```
后端默认监听 `:8080` 端口，自动创建 SQLite 数据库 `lab_system.db` 并自动填充 16 台设备及全部预置账号。

### 2. 启动前端服务 (Vue 3)
请先安装 Node.js 18 或以上版本（建议使用 Node.js 22）。首次启动需要安装前端依赖，根目录启动脚本会自动执行此步骤；手动启动时请先执行 `npm ci`。

双击运行根目录下的 `start_frontend.bat`，或在命令行中运行：
```bash
cd frontend
npm ci
npm run dev
```
打开浏览器访问：`http://localhost:5173` 即可进入系统。未登录用户将自动跳转至登录页。
